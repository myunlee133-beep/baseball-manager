# 리그 데이터 저장 (2026 KBO 실제 로스터) — 설계

선수 성장·퇴화 기능을 위한 3단계 중 1단계. 인터뷰(2026-09-29)에서 확정.

## 전체 로드맵

| 단계 | 내용 | 상태 |
|---|---|---|
| 1. 리그 데이터 저장 | 10개 구단 실제 로스터를 20–80 능력치로 저장, OVR/POT 계산, 저장 v2 | **이 문서** |
| 2. 시즌 진행 | 144경기 일정, 날짜 진행, 리그 전 경기 투구 엔진 시뮬레이션, 성적·순위 누적 | 별도 인터뷰 |
| 3. 성장·퇴화 | 월간 소폭 변동 + 오프시즌 나이 곡선, POT 연간 변동 | 별도 인터뷰 |

3단계를 위해 이미 확정한 것: 변화 시점은 시즌 종료 일괄 + 월 단위 소폭 변동, 곡선은 타자·투수 공통 하나, POT는 선수당 하나로 OVR 상한이며 매 오프시즌 POT 자체도 변동, 27세 이후는 나이 곡선대로 하락. 성장·퇴화는 저장된 개별 능력치를 움직인다.

## 목표

- 가상 선수(`seedPlayers`)를 2026 KBO 실제 10개 구단 로스터 410명으로 교체한다.
- 선수마다 20–80 개별 능력치를 **저장**한다. 엔진은 저장값을 그대로 쓴다(성적 역산 제거).
- 상대 9개 팀도 상태에 저장해 이후 시즌 진행·성장이 전 구단에 적용될 수 있게 한다.

## 범위 밖

외국인 선수 추가(원문 지시로 금지), 내 팀 선택 화면, 계약 로직(FA 연도는 저장만), 시즌 진행, 성장·퇴화, 연봉(원문에 값 없음).

## 데이터

- 원천: 사용자가 제공한 2026 개막 로스터 원문(10개 구단).
- 검토·승인된 결과:
  - [`2026-09-29-kbo-2026-roster.md`](2026-09-29-kbo-2026-roster.md): 410명 전체 명단 (1군 276, 2군 134)
  - [`2026-09-29-kbo-2026-roster-estimates.md`](2026-09-29-kbo-2026-roster-estimates.md): 빈 곳 추정 근거 (개별 추정 35명, 기본값 규칙, 원문 보정)
- 생성기: `scripts/kbo-2026/roster.mjs` (+ `gaps.mjs`). 위 명단 문서와 같은 결과를 낸다. 구현 시 여기서 `game/kbo-2026.js`를 생성한다.
- 원문의 `FA in 'YY`를 `faYear`로 추가 파싱해 저장한다(현재 생성기에는 없음).

### 선수 필드

```
{ id, name, team, group:'first'|'second'|'injured', pitcher, pos, role,   // role: 주전·벤치·SP·RP·SU·CL
  age, bats|throws: 'L'|'R'|'S'|null,                                      // null → 엔진에서 id 해시로 배정
  ratings: {contact,eye,power,speed,defense} | {velocity,stuff,control,stamina},
  pot, faYear|null, lastSeason: {원문 성적}|null, ...올해 누적 성적(0 시작) }
```

`ovr`는 저장하지 않고 계산한다.

### 변환 규칙 (승인됨)

- 기준: 20–80, 50 = 1군 주전 평균. 리그 풀(150타석+, 40이닝+) 대비 표준점수.
- 컨택 = 타율 .6 + 삼진율(역) .4 / 선구안 = 볼넷율 / 파워 = 순장타 .5 + 홈런율 .5.
- 구위 = K/9 .65 + H/9(역) .35 / 제구 = BB/9(역) / 구속 = 47 + 구위편차×.4 + 마무리·셋업 +3 + 나이 보정 / 체력 = 경기당 이닝.
- 스피드·수비는 원문에 없어 포지션 기본값 + 나이 감점 + 개별 조정(약 60명).
- 소표본은 타자 `PA/(PA+200)`, 투수 `IP/(IP+60)` 비중으로 기본값과 혼합.

### OVR (승인됨)

- 가중 평균: 타자 컨택 .30·파워 .30·선구 .20·스피드 .10·수비 .10(C·SS·CF 수비 .20), DH 컨택 .35·선구 .25·파워 .40, 선발 구위 .35·제구 .30·구속 .20·체력 .15, 불펜 구위 .45·제구 .30·구속 .25 − 3.
- `OVR = clamp(round(50 + 8 × (가중평균 − μ) / σ), 20, 80)`. μ, σ는 2026 개막 1군 가중평균의 평균·표준편차로 **상수 고정**.

### POT (승인됨)

- 공식: `POT = clamp(OVR + 성장여지(나이) + 편차, OVR, 80)`, 성장여지 ≤20 +25 · 21 +22 · 22 +18 · 23 +14 · 24 +11 · 25 +7 · 26 +4 · 27+ 0, 편차 = id 해시 −7~+7.
- 개별 지정 21명은 명단 문서 비고 참고. 지정값 < OVR이면 OVR로 올림. 문동주·정우주·김서현은 OVR+3.

## 구성

| 파일 | 변경 |
|---|---|
| `game/kbo-2026.js` | **신규**. 생성기 출력(410명 고정 데이터) |
| `game/player-ratings.js` | **신규**. 가중치·μ·σ 상수, `ovr(player)`, `clampPot(player)` |
| `model.js` | 최소 수정: `teams`를 실제 구단명으로, `seedPlayers` 대신 `kbo-2026` 로드, `initialState`가 10개 구단 전원과 원문 보직 기반 라인업·로테이션·불펜 역할을 만든다(선발이 5명 미만인 팀은 체력 높은 불펜으로 채움). 기본 팀은 KT |
| `game-bridge.js` | `toEngineHitter/Pitcher`가 `ratings`를 그대로 사용. 좌우 null이면 기존 해시. 성적 역산(및 BABIP 우선순위 버그 줄) 제거. 상대 팀도 `state.players`에서 읽음 |
| `app.js` | 최소 수정: `seedPlayers(i)` 호출부를 상태 조회로, 날짜 표시 "2026 시즌 개막 전", 기록실은 `lastSeason`을 "2025" 라벨로, OVR은 계산값 표시 |
| `README.md` | 가상 데이터 안내 수정, 실명 사용·라이선스 주의 한 줄 |

`model.js`·`app.js`는 공유 파일이므로 PR 설명에 상태 구조 변경을 명시한다(AGENTS.md).

## 저장

- 키 `dugout-prototype-v1` → `dugout-prototype-v2`. v1이 있으면 버리고 새로 시작, 안내 토스트 1회. 가상 선수와 실제 선수는 대응 관계가 없어 마이그레이션하지 않는다.
- 진행 중 경기 `dugout-active-game-v1`도 함께 삭제.

## 오류 처리

- 저장 데이터 파싱 실패 → 기존처럼 `initialState()`.
- 좌우 미상 → 해시 배정, 포지션 미상(`IF`/`OF`) → 엔진 수비 자격에서 내야·외야 일반으로 취급.

## 테스트 (`tests/league-data.test.mjs`)

- 410명, 팀별 인원, 1군 선발 ≥ 4(한화 원문 4명), 모든 능력치 20–80 정수, `pot ≥ ovr`, 지정 POT 21명 값 일치.
- 1군 OVR 평균 50±1, 표준편차 8±1.
- 브리지: 저장 능력치가 엔진 입력과 같다. 10개 구단 각각 상대로 한 경기씩 `final`까지 진행.
- 저장: v1 키가 있으면 v2 초기 상태로 시작하고 v1 경기 저장이 지워진다.
- 기존 `npm test` 전부 통과.

## 알려진 한계

- 원태인처럼 삼진이 적은 에이스는 구위가 낮게 나온다(평균자책 미반영).
- 좌우 미상 125명(대부분 2군)은 해시 배정.
- 외국인 선수가 없어 실제보다 로테이션이 약하다.
- 개별 추정 값은 2025년까지의 실제 커리어에 대한 추정이며 확신도가 낮은 선수가 있다(estimates 문서 표기).

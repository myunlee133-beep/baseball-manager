# 시즌 진행 — 설계

선수 성장·퇴화를 위한 3단계 중 2단계. 인터뷰(2026-09-29)에서 확정. 전제: [1단계 리그 데이터](2026-09-29-league-data-design.md) 구현 완료(`feat/league-data`), 인계 메모는 [handoff](2026-09-29-season-progression-handoff.md).

## 목표

- 2026 개막 전에서 시작해 144경기 일정을 날짜 단위로 진행한다.
- 날짜를 넘기면 그날 리그 전 경기(최대 5경기)를 투구 단위 엔진으로 시뮬레이션하고 일정·순위·선수 성적·박스스코어에 반영한다.
- 체력을 시즌 운영의 핵심 변수로 만든다(소모·회복·자동 휴식·능력치 감소).
- 3단계 연결점 `monthlyTick`, `offseasonTick`을 호출하는 자리만 만든다(내용은 빈 함수).

## 범위 밖

AI 구단 1·2군 이동(성장 시스템 고도화 이후), 부상 발생·회복일 차감(후속), 포스트시즌, 성장·퇴화 내용(3단계), WAR, 우천 취소, Web Worker, IndexedDB.

## 확정한 결정

| 항목 | 결정 |
|---|---|
| 일정 | KBO식. 팀당 144경기, 상대별 16경기(홈 8·원정 8). 3연전 위주 + 일부 2연전, 월요일 휴식, 시리즈는 월요일을 넘지 않음. 7월 중순 올스타 휴식 4일. 2026 개막 3/28(토), 종료일은 생성 결과(9월 말 무렵). 시드 고정 |
| 포스트시즌 | 없음. 144경기 후 순위 확정 → 오프시즌 → 다음 시즌 |
| 내 팀 경기 | [다음 날]은 기존 LIVE GAME으로 직접 진행, 여러 날 진행은 내 경기도 자동 시뮬 |
| 진행 단위 | 다음 날 / 다음 주(7일) / 월말 / 시즌 끝 + 중단(그날이 끝나면 멈춤) |
| 실행 방식 | 메인 스레드, 경기마다 `setTimeout(0)`으로 양보, 하루 끝날 때 저장. 목표 시즌 전체 ≤ 90초 |
| AI 운영 | 1단계 기본 편성 고정 + 로테이션 순번 + 체력 기반 자동 휴식. 1·2군 이동 없음 |
| 부상 | 이번 범위에서 제외. `injury`/`days`를 건드리지 않음 |
| 박스스코어 | 720경기 전부 보관(시즌 약 1.6MB), 별도 키. 새 시즌 시작 때 이전 연도 삭제 |
| 화면 | 새 화면 없이 기존 홈·달력·박스스코어·기록실·헤더를 실제 데이터로 교체 + 진행 버튼·진행 모달 |
| 시즌 종료 | 종료 모달 → [다음 시즌으로] → 성적 보관·나이 +1·체력 100·`offseasonTick`·새 일정 |

## 구성

| 파일 | 변경 |
|---|---|
| `game/league-schedule.js` | **신규**. `buildSchedule(year, seed)` → 경기 배열 `{id, date, home, away}` |
| `game/season-fatigue.js` | **신규**. 체력 상수, `spendEnergy(box, ctx)`, `recoverDay(players, date)`, `restPlan(team, players)`, `energyPenalty(ratings, energy)` |
| `game/league-season.js` | **신규**. `createSeason(year)`, `gamesOn(season, date)`, `playGame`, `finishDay`, `standings`, `endSeason`, `startNextSeason`, 빈 함수 `monthlyTick(state)`·`offseasonTick(state)`, `loadBox(id)`·`saveBox(id, box)` |
| `season-runner.js` | **신규**. `advance(state, until, {onProgress, shouldStop})` 비동기 진행 |
| `game-bridge.js` | 팀 구성에 `restPlan`·`energyPenalty` 적용. LIVE GAME 결과를 시즌에 반영하는 함수 추가, 진행 중 경기에 `gameId` 연결 |
| `model.js` | 최소 수정: 상태에 `season`·선수 필드 추가, 저장 v2→v3 마이그레이션 |
| `app.js` | 최소 수정: 화면 연결(아래 "화면"), 진행 버튼·모달 |

`model.js`·`app.js`는 공유 파일이므로 PR 설명에 상태 구조 변경을 명시한다(AGENTS.md). `game/` 기존 엔진 파일(이식 원본)과 `game/season.js`는 수정하지 않는다. `season.js`는 원본 팀 데이터·저장 키·upstream 테스트에 묶여 있어 재사용하지 않는다.

## 저장 데이터

### 본 상태 `dugout-prototype-v3`

1단계 상태(`players` = 내 팀 KT·팀 번호 0, `league[1..9]`, `order`/`field`/`rotation`/`bullpen`/`strategy`)에 추가:

```js
season: {
  year: 2026,
  date: '2026-03-28',              // 아직 처리하지 않은 오늘
  phase: 'preseason' | 'regular' | 'ended',
  schedule: [{ id, date, home, away, status: 'scheduled' | 'final',
               score: { home, away }, innings, decisions: { win, loss, save } }],
  standings: { [팀번호]: { w, l, t, rf, ra, last: ['W','L','T', ...최근 5] } },
  rotationTurn: { [팀번호]: 0 },     // AI 팀 다음 선발 순번. 내 팀은 strategy.next
  autoRestMine: true,                // 여러 날 진행 시 내 팀 자동 휴식
  news: [ ...최근 20줄 ],
}
선수 필드 추가:
  energy        // 기존 필드를 실제 값(0–100)으로 사용
  stats: { batting: {엔진 기록 줄}, pitching: {엔진 기록 줄} }  // 올해 누적, 0인 항목 생략
  lastPitched   // 'YYYY-MM-DD' | null, 연투 계산용
  history: { [연도]: { batting, pitching } }  // 시즌 종료 때 채움
```

- 2025 원문 성적은 1단계처럼 선수 기록 필드(`avg`, `era` 등)에 그대로 둔다. 올해 성적은 `stats`에만 쌓는다.
- 승률·승차·최근 5경기, 타율·OPS·평균자책 등 비율 지표는 저장하지 않고 계산한다.
- 기록 줄은 엔진의 `emptyBattingLine`/`emptyPitchingLine` 형식(승·패·세이브·홀드 포함)을 그대로 합산한다.

### 박스스코어 `dugout-boxes-{연도}`

```js
{ [경기id]: { lineScore, hits, errors, bat: { 선수id: 기록 줄 }, pit: { 선수id: 기록 줄 } } }
```

- 실측 경기당 약 2.2KB(0인 항목 제외), 시즌 약 1.6MB. 본 상태(약 256KB)와 합쳐 약 2MB로 localStorage 한도(약 5MB) 안.
- 접근은 `loadBox`/`saveBox`로만 한다. 여러 시즌 보관이 필요해지면 이 두 함수만 IndexedDB로 바꾼다.
- 새 시즌 시작 때 이전 연도 키를 지운다.

### 진행 중 경기

기존 `dugout-active-game-v1`을 유지하고 `gameId`를 추가해 일정의 경기와 연결한다.

### 마이그레이션 v2 → v3

v2는 개막 전 상태라 진행 기록이 없다. `season`(2026 개막 전), 전원 `energy: 100`, 빈 `stats`, `lastPitched: null`, 빈 `history`를 채우고 사용자 편성은 유지한다. 파싱 실패 시 `initialState()`.

## 일정 생성

- 팀 간 16경기 = 3연전 4개 + 2연전 2개, 홈 8·원정 8.
- 라운드(10팀이 5경기씩 동시에 치르는 시리즈 묶음)를 원형 로빈으로 만들고 달력에 배치한다. 월요일과 올스타 휴식일은 경기 없음, 한 시리즈는 월요일을 넘지 않는다. 개막 주말(3/28–29)은 2연전 라운드.
- 시드 고정(`year` 기반)으로 매번 같은 일정. 정확한 라운드 배치 규칙은 구현 계획에서 정하고 테스트로 제약을 검증한다.

## 체력 모델 (`game/season-fatigue.js`)

모든 수치는 상수로 모아 두고 시즌 스모크 테스트 결과로 조정한다.

### 경기 뒤 소모 (박스스코어로 계산)

| 대상 | 소모 |
|---|---|
| 선발 야수 | −10 (포수 −15, 지명타자 −5), 연장 이닝마다 −1 추가 |
| 교체 출전 야수 | −4 |
| 선발투수 | 투구 수 × 0.6 |
| 불펜투수 | 투구 수 × 1.0, 전날도 등판 +10, 3연투 +20 |

### 매일 회복 (아침, 휴식일 포함)

- 야수 +6, 투수 +10. 전날 경기에 나가지 않은 선수 +50%.
- 나이 33세 이상 −20%, 25세 이하 +10%. 상한 100.

예: 매일 나가는 주전 야수는 주당 약 −15, 포수 약 −45. 100구 선발은 40까지 떨어지고 5일 뒤 약 95.

### 능력치 감소 (엔진에 넘기기 직전)

체력 70 미만이면 `(70 − 체력) × 0.3`만큼 뺀다. 타자는 컨택·파워·스피드·수비, 투수는 구속·구위·제구. 20 하한은 두지 않고 엔진 입력 범위(5–90)로만 자른다. 엔진 자체의 경기 중 피로(`fatigue = 100 − energy`, 투구 수 감소)는 그대로 겹친다.

### 자동 휴식·기용 (`restPlan`)

AI 팀 전부, 그리고 여러 날 진행 중 `autoRestMine`이 켜진 내 팀에 적용한다. [다음 날] 직접 진행에는 적용하지 않는다.

- 야수: 체력 45 미만(포수 55 미만) 주전은 휴식. 벤치에서 체력이 가장 높은 선수로 대체하되 수비 자격은 `assignPositions`로 검사. 대체 불가면 그대로 출전.
- 선발: 순번 선발의 체력이 70 미만이면 체력 70 이상인 다음 선발을 앞당긴다. 없으면 체력이 가장 높은 불펜이 선발(불펜 데이). 순번은 실제 선발한 투수 다음으로 전진.
- 불펜: 체력 30 미만은 그날 엔진에 넘기지 않는다. 등판 가능 투수가 하나도 없으면 제한을 풀어 전원 등판 가능.

## 진행 흐름

### 하루 처리 (날짜 D)

1. D가 새 달의 첫날이면(개막일 제외) `monthlyTick(state)`.
2. 아침 회복.
3. D의 경기마다: 기본 편성(`teamSetup` / 내 편성) → `restPlan` → `energyPenalty` → 엔진 팀 → `simulateGame`(시드 = 경기id·연도 해시) → 일정 결과·순위·`stats`·박스스코어·체력 소모·`lastPitched`·로테이션 순번·소식 반영.
4. 날짜 +1. 남은 경기가 없으면 `phase: 'ended'`, 종료 모달.

휴식일은 1·2·4만 실행한다.

### [다음 날]

- 오늘 내 경기가 있으면 경기 전 점검 → LIVE GAME 모달. 체력 감소는 적용, 자동 휴식은 미적용.
- 경기가 끝나면 내 경기 반영 → 나머지 경기 시뮬 → 하루 마무리 → 결과 요약 토스트.
- 모달을 닫으면 진행 중 경기로 저장되고, [다음 날]로 이어서 한다.
- 내 경기가 없으면 바로 하루 진행.

### [다음 주 / 월말 / 시즌 끝]

- 목표일: 7일 뒤 / 그달 마지막 날 / 마지막 경기일.
- 진행 모달: 진행률(경기 수 기준), 현재 날짜, 내 팀 전적 변화, [중단].
- 내 경기는 내 타순·수비·로테이션(`strategy.next`부터 순번)으로 자동 시뮬, `autoRestMine` 적용.
- 진행 중 LIVE GAME이 있으면 확인 후 현재 상태에서 끝까지 시뮬하고 진행.
- 내 라인업이 무효(9명 미만·수비 자격 불가·선발 없음)면 그날 직전에서 멈추고 안내.
- 하루마다 저장한다. 중단·탭 종료 시 마지막으로 끝난 날까지 보존.

### 시즌 종료 → 다음 시즌

종료 모달(최종 순위·내 팀 성적) → [다음 시즌으로] → 선수 `stats`를 `history[연도]`로 이동 → 나이 +1, 체력 100 → `offseasonTick(state)` → 이전 연도 박스스코어 키 삭제 → 다음 연도 일정 생성, 순위·`stats`·`rotationTurn`·`lastPitched` 초기화 → `phase: 'preseason'`.

## 화면 (`app.js`)

- 헤더: 게임 날짜 "2026. 04. 12 (일)" + "정규시즌 23경기 · 12승 10패 1무". 개막 전·종료 후는 단계 표시.
- 홈 상단: [다음 날] [다음 주] [월말] [시즌 끝] 버튼, "내 팀 자동 휴식" 토글.
- 홈 순위표: 실제 승·패·무·승률·승차·최근 5경기.
- 다음 경기 브리핑: 실제 상대·홈/원정·양 팀 예상 선발(체력 포함)·올해 성적(없으면 2025 원문).
- 리그 소식: `season.news`. "체력 관리 필요" 알림은 체력 60 미만 선수.
- 스케줄 달력: 저장 일정. 내 경기 칸은 상대·점수, 날짜 클릭 시 그날 전 경기 목록 → 경기 클릭 시 실제 박스스코어. "가상 경기 기록" 문구 제거.
- 기록실: 연도 선택(올해 / 2025 / `history` 연도), 규정타석(팀 경기 수 × 3.1)·규정이닝(× 1) 필터, 팀 탭은 올해 팀 합계, WAR은 "—".
- 로스터·라인업: 기존 체력 표시가 실제 값.

## 오류 처리

- 저장 용량 초과(`QuotaExceededError`): 진행을 멈추고 "저장 공간 부족" 모달. 그날 결과는 메모리에 남아 재시도 가능.
- 엔진 예외: 해당 날짜 직전에서 멈추고 오류 토스트. 끝난 날은 저장돼 있음.
- 자동 휴식 대체 불가·등판 가능 투수 없음: 위 규칙대로 완화.

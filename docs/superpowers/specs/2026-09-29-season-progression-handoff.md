# 2단계 시즌 진행 — 인터뷰 인계 메모

2026-09-29 인터뷰 세션에서 넘기는 맥락. 2단계는 이 메모와 [1단계 설계](2026-09-29-league-data-design.md)를 읽고 **사용자 인터뷰부터** 시작한다(바로 구현하지 않는다).

## 이미 확정된 결정

- 성장·퇴화(3단계)를 실행할 계기로 **날짜 진행 기능을 실제로 만든다**(임시 버튼 아님).
- 날짜를 넘길 때 **리그 전 경기(하루 5경기)를 투구 단위 엔진으로 시뮬레이션**하고 결과를 일정·성적·순위에 반영한다.
- 3단계 연결점: 월이 바뀔 때 월간 소폭 성장(`monthlyTick`), 시즌 종료 시 오프시즌 곡선·POT 변동(`offseasonTick`). 2단계는 이 두 훅을 호출할 자리만 만든다.
- 시즌은 **2026 개막 전**에서 시작, 올해 성적은 0부터. 1단계에서 기록실은 원문 2025 기록(`lastSeason`)을 임시로 보여준다 → 2단계에서 실제 누적 성적으로 교체.
- 작업 규칙은 `AGENTS.md`: 작은 PR 하나, 새 로직은 새 파일, `model.js`·`app.js`는 최소 수정, 저장 필드 변경 시 버전·마이그레이션.

## 전제 (1단계 완료 후 상태)

- `state.players`에 10개 구단 410명 저장, 선수마다 20–80 `ratings`, `pot`, `lastSeason`, 계산 OVR.
- `game-bridge.js`는 저장 능력치를 그대로 엔진에 넘긴다. 저장 키 `dugout-prototype-v2`.
- 1단계가 머지되기 전이면 브랜치 `claude/game-player-growth-decay-b60703`(로컬, 추후 `feat/league-data`) 위에서 작업한다.

## 코드에서 확인한 사실

- 날짜는 `app.js`에 `2033. 06. 14`로 하드코딩(1단계에서 "개막 전" 표시로 바뀜). 게임 내 시간 흐름 없음.
- `model.js`의 `schedule(month)`는 월마다 계산식으로 만든 **가짜 일정·결과**. 저장되지 않음.
- `game/season.js`(원본 이식)에 `createMiniSeason(24일)`, `todayGames`, `standingOrder`, `startTodayGame`, `recordFinishedUserGame`, `saveSeason/loadSeason`(키 `nine-mini-season-v2`)이 있다. 재사용 가능성 검토 대상.
- 엔진 속도 실측: 1경기 약 **88ms** → 하루 5경기 약 0.45초, 시즌 약 720경기 약 **1분**. "시즌 끝까지 진행"에는 분할 실행·진행률 표시가 필요.
- 진행 중 경기는 별도 키 `dugout-active-game-v1`로 저장(카운트·난수 포함).

## 인터뷰에서 물어볼 것 (제안 순서)

1. 시즌 구조: 144경기, 개막일, 올스타 휴식, 우천 취소·재편성 여부, 포스트시즌 포함 여부.
2. 내 팀 경기: 직접 진행(투구 단위 UI)과 자동 시뮬 중 무엇이 기본인지, 선택 가능한지.
3. 진행 단위: 다음 날 / 다음 주 / 월말 / 시즌 끝 중 무엇을 제공할지, 중간 중단.
4. AI 팀 운영: 라인업·로테이션·불펜 자동 편성, 1·2군 이동, 피로도 누적과 회복.
5. 부상: 경기 중 발생·회복일 진행을 이번 범위에 넣을지.
6. 성적 누적: 저장할 필드(기록실 기본/세부 지표 전부?), 박스스코어 보관 범위(저장 용량).
7. 순위·기록 화면: 기존 화면을 실제 데이터로 연결하는 범위.
8. 성능: 분할 실행 방식(메인 스레드 청크 vs Web Worker), 목표 시간.
